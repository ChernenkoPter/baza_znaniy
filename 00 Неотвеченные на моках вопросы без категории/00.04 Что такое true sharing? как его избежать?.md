True sharing - параллельная работа с одной переменной из разных потоков (хотя бы один пишет), влияет на производительность кода. Если нет синхронизации - то еще на корректность.
- уменьшение количества обращений к переменной
- замена переменной на несколько независимых с последующим мерджем результатов
  - striping - потоки записывают результаты независимо, но при чтении необходимо агрегировать их результаты, бывают за счет обычный массив/массив std::atomic + паддинг/выравнивание, thread_local переменные + агрегация результатов
  - использовать `std::memory_order_relaxed`, если атомарная переменная самодостаточна - счетчик/статистика, а не флаг/сигнал для другой переменной, иначе для нее надо использовать `memory_order_release/_acquire`
