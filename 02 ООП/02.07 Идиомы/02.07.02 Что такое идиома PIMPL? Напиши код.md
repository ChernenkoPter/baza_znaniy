Pointer to IMPLementation - идиома скрытия деталей реализации через указатель на неполный тип. Из-за того то все детали реализации скрыты, уменьшается зависимости и время компиляции - при изменении деталей реализации не требуется перекомпилировать все объектные файлы, включающие измененный заголовочный файл
```
// widget.h
class Widget {
public:
    Widget();
    ~Widget(); 
    void doTask();
private:
    struct Impl;
    std::unique_prt<Impl> pImpl;
};

// widget.cpp
struct Widget::Impl { /* вся внутренняя релизация */ };

// В заголовочном файле тип Impl неполный, поэтому при включении в единицы трансляции, где нет реализации Impl, будет ошибка компиляции.
// Поэтому писать
Widget::Widget() : pImpl(std::make_unique<Impl>()) {}
Widget::~Widget() = default; // требуется для std::unique_ptr с неполным типом
Widget::doTask() { /* реализация через методы Impl */ }
// надо единице трансляции с реализацией Impl
```
