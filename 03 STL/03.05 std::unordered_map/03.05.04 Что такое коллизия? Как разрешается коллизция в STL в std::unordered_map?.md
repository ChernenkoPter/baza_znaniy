Коллизия - в контексте unordered_map это совпадение индекса бакета (`hash(key) % bucket_count()`) для различных входных значений.

Стандарт не специфицирует как колизии должны разрешаться.
В gcc, clang и msvc хэш таблица хранит бакеты со списком узлов (это метод цепочек). При работе с ключом вычисляется его бакет, а дальше идет сравнение с ключом хранящимся в узле, пока узлы не закончатся или пока не будет найден нужный. 

Кроме метода цепочек есть другие методы, самый "популярный" - метод открытой адресации - в бакетах хранятся теги OCCUPIED(тогда есть ключ и значение)/DELETED/EMPTY, при коллизии с i-тым бакете индекс нового бакета вычисляется:
- при линейном пробировании - `(hash(key) + i) % bucket_count()`
- при квадратичном пробирвании - `(hash(key) + c1*i + c2*i*i) % bucket_count()`
- при двойном хешировании - `(hash_1(key) + i*hash_2(key)) % bucket_count()`

В методе открытой адресации отслеживается не только количество элементов, но и доля удаленных элементов, при превышении некоторого лимита происходит рехэш
