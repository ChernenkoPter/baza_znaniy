По логической модели: 
- реляционная - данные в отношениях(таблицах) с атрибутами и доменами, запросы на sql, результат - тоже отношение, связи восстанавливаются join-ом
- key-value - доступ только по ключу
- графовая - данные хранятся в связанных друг с другом узлах, что упрощает глубокие обходы
- векторная - хранят эмбеддинги, которые отражают смысл, поиск ведется не по точному совпадению, а по схожести векторов 
- документная - для json/bson
- объекто-ориентированная - вытеснена реляционными + ORM (object relational mapping - преобразует объект в запись и обратно), т.к. не решили проблему object-relational impedance mismatch (наследование, идентичность не ложатся на таблицы)
- wide-column - nosql аналог key-value, но в качестве значений - пары имя семейства + семейство, где семейство - набор пар ключ + значение
- иерархическая - дерево записей с одним родителем, применяются в файловых системах
- сетевая - расширение иерархической, где связи могут иметь несколько родителей, вытеснена реляционными

По назначению:
- OLAP - мало запросов, но все читают миллионы строк, важна пропускная способность, организованы как column store
- OLTP - много маленьких транзакций, важна низкая задержка, организованы как row store
- кеш - быстрый доступ к горячим данным
- time-series - метрики и логи, запись только в конец, удаление старых данных, агрегатные окна
- поисковые - поиск по тексту
- векторные - поиск по сходству эмбеддингов для ML
- встраиваемые - БД внутри приложения, без отдельного сервера
